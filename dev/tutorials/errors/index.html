Printing and error messages

A tour of how JuliaTopology prints objects, categories and errors. Colors are shown only when the output supports them; to run this script yourself in a terminal, force them with julia --color=yes --project=. examples/errors.jl.

using JuliaTopology
using StyledStrings: Face, withfaces
import JuliaTopology: checkInCategory, checkInterface, name
using JuliaTopology: @checkCallable

# Run `thunk` and print the error it throws, or say that none was thrown
function demo(thunk)
    try
        thunk()
        println("(no error)")
    catch e
        showerror(stdout, e)
    end
end

Compact display

show(io, x), used inside messages and collections, gives one line per value.

S = FinSet[Set([1, 2, 3])]
x = OIC(1, ascat(S); force=true)
f = OIC(:f, Hom(S, S); force=true)   ## a morphism with no behavior defined
g = OIC(:g, Hom(x, x); force=true)   ## a morphism between elements of S

println(S)            ## an object in a category
println(x)            ## an element of ascat(S)
println(f)            ## a morphism in FinSet
println(g)            ## a morphism in ascat(S)
println(FinSet)       ## a category
println(ascat(S))    ## an object regarded as a category
println(Hom(S, S))    ## a Hom category
println([x, x])       ## inside a collection

    println("\n")

Default maps of a morphism

A morphism which does not define how it maps elements explains which method to overload. The call and method lines are highlighted as Julia code.

demo(() -> f(x))
InterfaceViolation: The type
    Symbol
does not define how its objects in Hom(Set([3, 2, 1]), Set([3, 2, 1])) map the elements of their domain, so the morphism
    :f ∈ Hom(Set([3, 2, 1]), Set([3, 2, 1]))
cannot be applied to
    1 ∈ ascat(Set([3, 2, 1])).
When appropriate, you may define this map by overloading
    f(x)
where
    f is any element of Hom(Set([3, 2, 1]), Set([3, 2, 1])) represented by that type,
    x is any element of ascat(Set([3, 2, 1])),
that is, the method
    (f::OIC{Symbol, Hom{Set{Int64}, Set{Int64}, CatFinSet}})(x::OIC{<:Any, OICAsCat{Set{Int64}, CatFinSet}})
demo(() -> f(g))
InterfaceViolation: The type
    Symbol
does not define how its objects in Hom(Set([3, 2, 1]), Set([3, 2, 1])) map the morphisms between elements of their domain, so the morphism
    :f ∈ Hom(Set([3, 2, 1]), Set([3, 2, 1]))
cannot be applied to
    :g ∈ Hom(1, 1).
When appropriate, you may define this map by overloading
    f(g)
where
    f is any element of Hom(Set([3, 2, 1]), Set([3, 2, 1])) represented by that type,
    g is any element of Hom(1, 1),
that is, the method
    (f::OIC{Symbol, Hom{Set{Int64}, Set{Int64}, CatFinSet}})(g::OIC{<:Any, Hom{Int64, Int64, OICAsCat{Set{Int64}, CatFinSet}}})

Overload hints elsewhere

A minimal category, with no interface check and no canonical morphisms:

struct CatToy <: Category end
name(::CatToy) = "Toy"
Toy = CatToy()
checkInCategory(::Union{Int, String}, ::CatToy) = true

No canonical morphism between two objects, or between two categories:

demo(() -> canonicalHom(S, S))
NoCanonicalHomError: There is no unique map from
    Set([3, 2, 1]) ∈ FinSet
to
    Set([3, 2, 1]) ∈ FinSet
since it has 3 elements and the second has 3. A map of finite sets is unique only into a one-element set or out of the empty set.
demo(() -> canonicalHom(Toy, FinSet))
NoCanonicalHomError: No canonical morphism is defined between the categories
    Toy
and
    FinSet.
When appropriate, you may define a canonical morphism between these by overloading
    canonicalHom(A, B)
where
    A is the category Toy,
    B is the category FinSet,
that is, the method
    canonicalHom(A::Main.CatToy, B::CatFinSet)

A value the category does not say anything about:

demo(() -> OIC(3.5, Toy))
NotInCategory: The value
    3.5
cannot be regarded as an object of Toy, since Toy does not say whether values of type Float64 are among its objects. Most likely they are not meant to be. If they are, you may say so by overloading
    checkInCategory(obj, cat)
where
    obj is any value of type Float64,
    cat is the category Toy,
that is, the method
    checkInCategory(obj::Float64, cat::Main.CatToy)
or skip the check for this one value with `force=true`.

@checkCallable: here, strings in Toy must be callable with an Int.

checkInterface(obj::String, cat::CatToy) = @checkCallable obj cat Tuple{Int}
demo(() -> OIC("hello", Toy))
InterfaceViolation: The category Toy requires its objects to be callable as f(x1), but the type String does not define this, so it cannot represent
    "hello".
When appropriate, you may define it by overloading
    f(x1)
where
    f is any object of Toy represented by values of type String,
    x1 is any value of type Int64,
that is, the method
    (f::OIC{String, Main.CatToy})(x1::Int64)
or skip the check for this one value with `force=true`.

A type which iterates but has no length is not a finite set:

struct Bag end
Base.iterate(::Bag, state=nothing) = nothing
demo(() -> FinSet[Bag()])
NotInCategory: The value
    Main.Bag()
is not an object of FinSet, since objects of FinSet must be finite collections, but values of type Main.Bag are missing the methods
    Base.length(x::Main.Bag)
When appropriate, you may define them, or skip this check for this one value with `force=true`.

FinSet's check that iterating over its objects has a known length:

struct Bag2 end
Base.iterate(::Bag2, state=nothing) = nothing
Base.length(::Bag2) = 0
Base.eltype(::Type{Bag2}) = Int
Base.in(::Int, ::Bag2) = false
Base.IteratorSize(::Type{OIC{Bag2, CatFinSet}}) = Base.SizeUnknown()
demo(() -> FinSet[Bag2()])
InterfaceViolation: The category FinSet requires iterating over its objects to have a known length, which is not the case for objects represented by values of type Main.Bag2, such as
    Main.Bag2().
The method
    Base.IteratorSize(::Type{OIC{Main.Bag2, CatFinSet}})
returns Base.SizeUnknown() where it should return Base.HasLength().

Plain values

Values not wrapped in a category get their own color.

demo(() -> Hom(S, 3))
ArgumentError: The codomain of a Hom must be an ObjectInCategory. However,
    3
is not. You may wrap it in a category first, e.g. FinSet[x].
demo(() -> FinCard[3.5])
NotInCategory: The value
    3.5
is not an object of FinCard, since the objects of FinCard are the non-negative values of type Int, and it is a Float64.
demo(() -> OIC(7, ascat(S)))
NotInCategory: The value
    7
is not an element of Set([3, 2, 1]), so it is not an object of ascat(Set([3, 2, 1])).

How colors are applied

Colors are attached to the text rather than baked in as escape codes, so repr and string give plain text.

println(repr(repr(S)))
"Set([3, 2, 1]) ∈ FinSet"

Code snippets in messages are syntax highlighted as Julia:

println(JuliaTopology.codeclr("canonicalHom(A::OIC{<:Any, CatFinSet}, B::CatFinCard)"))
canonicalHom(A::OIC{<:Any, CatFinSet}, B::CatFinCard)

@annotated builds a message which keeps the colors of what it interpolates:

println(JuliaTopology.@annotated "The object $x and the value $(JuliaTopology.valclr(7))")
The object 1 ∈ ascat(Set([3, 2, 1])) and the value 7

Each color is a face, which can be restyled, here only temporarily. To change it permanently, set it in ~/.julia/config/faces.toml, e.g.

[juliatopology]
object = { foreground = "red" }
withfaces(:juliatopology_object => Face(foreground=:red, underline=true)) do
    println(S)
end
Set([3, 2, 1]) ∈ FinSet

Colors can be switched off, and back on, at any time:

JuliaTopology.setColorfulOutput!(false)
println(S)
JuliaTopology.setColorfulOutput!(true)
println(S)
Set([3, 2, 1]) ∈ FinSet
Set([3, 2, 1]) ∈ FinSet
